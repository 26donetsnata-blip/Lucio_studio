# Проект «Аркана» — Таро и Нумерология (iOS MVP)

Инструкция для агента (Claude Code или любого другого), продолжающего работу над
этим проектом. Прочитай перед тем, как что-то менять.

## Что это

Нативное iOS-приложение (Swift/SwiftUI), два раздела: Таро и Нумерология.
Тёмная тема, без регистрации, история — только локально (SwiftData).
Полное ТЗ и контент — в `extracted/` (см. ниже), не менять эти файлы, они —
источник истины по требованиям.

**Обязательно прочитай [`PRODUCT_MISSION.md`](PRODUCT_MISSION.md)** — там
зафиксировано, какую проблему клиента решает приложение (полный, лаконичный,
понятный и достоверный ответ по методике, без выдумывания). Это критерий,
по которому нужно сверять любой новый контент и фичу.

**И [`DESIGN_SYSTEM.md`](DESIGN_SYSTEM.md)** — единый источник истины по
визуалу (цвета, типографика, компоненты, анимации), выведенный из референсов
заказчика в `extracted/`. Любое изменение `Theme.swift`/`Components.swift`
сверяй с этим файлом и наоборот.

## Принятые решения (без обратной связи от заказчика — см. диалог в сессии)

- **Стек:** Swift + SwiftUI, iOS 17+, SwiftData для локальной истории. Никакого бэкенда в MVP.
- **Ассеты:** реальной графики/звука от заказчика нет (только 3 png-мокапа для стиля). Все визуалы — программные заглушки в стиле мокапов (звёздное небо, карточные рубашки/лица без иллюстраций). Когда заказчик пришлёт финальные ассеты — подставляются файлами, без переделки кода (в `SoundService` и в местах отрисовки карт уже предусмотрены точки подмены).
- **Нумерология:** таблица "буква→число" и банк текстов прогноза/совместимости в `tarot_numerologiya_kontent_v2.md` помечены заказчиком как черновые (нужна проверка нумерологом) — используются как есть, вынесены в JSON, чтобы поправить одним файлом без изменения кода.
- **Архитектурные заделы под Этап 2** (уже в схеме, не требуют переделки): `TarotCardInterpretations.personalized` (авторские тексты по сочетаниям карт), `EntitlementProvider` (монетизация), `HistoryRepository` — протокол, под который можно подставить облачную синхронизацию.

## Важная особенность окружения

В песочнице, где стартовала разработка, установлены только Command Line Tools,
**полного Xcode нет** — нельзя было собрать/прогнать проект в симуляторе и
проверить визуально. Код писался и проверялся насколько возможно без него
(логика — через `swift`-скрипты отдельно от UIKit/SwiftUI). **Перед тем как
считать фичу готовой, обязательно собери и прогони проект в Xcode/симуляторе
на своей стороне** и сверь с мокапами (`extracted/*.png`).

## Как собрать

```bash
brew install xcodegen   # если ещё не установлен
cd TarotNumerology
xcodegen generate
open TarotNumerology.xcodeproj
```
Дальше — обычная сборка и запуск в Xcode (Cmd+R) на симуляторе iPhone.

## Статус реализации

Реализовано полностью (код, без визуальной проверки в симуляторе — см. "Важная
особенность окружения"): дизайн-система, персистентность, entitlements,
онбординг, главный экран, Таро (78 карт, выбор расклада, флип, сохранение в

и типы проверены отдельно от реальной сборки (см. отчёт агента в сессии).

## Открытые вопросы (нерешённые заказчиком, см. ТЗ раздел 9)

- Финальный вординг текстов интерфейса.
- Таблица "буква→число" **проверена программно** — это стандартный
  циклический метод 1-9 по 33 буквам русского алфавита, а не произвольная
  выдумка (см. комментарий в `letter_values.json`). Остаётся уточнить у
  нумеролога только классификацию Й/Ъ/Ь как гласная/согласная в
  `NumerologyCalculator.sumLetterValues` — сейчас они считаются согласными.
- Банк прогнозов дня расширен до 2-3 вариантов на число (было по 1) — контент
  предполагает до 9-12, можно продолжать пополнять `day_forecast_bank.json`
  без изменения кода.
- Таблица совместимости 9×9 переписана на более естественные формулировки
  (было — механически сгенерированные фразы). Всё ещё черновик по существу
  (метод "только по числу судьбы" — самый простой MVP-вариант из документа),
  нужна проверка нумерологом перед релизом.
- Финальная графика (иллюстрации карт, hero-изображение, звук переворота).
- **Несостыковка в исходниках:** в `tz_tarot_app.md` формула числа судьбы для
  14.03.1994 явно даёт 4 (1+4+0+3+1+9+9+4=31→4), а в мокапе `numerology_screen.png`
  для той же даты (Мария, 14.03.1994) на карточке показано число судьбы 3.
  Мокап — "прототип экранов, без функционала", поэтому в коде реализована
  формула из текстового ТЗ (более авторитетный источник по PRODUCT_MISSION.md),
  но стоит сверить с заказчиком/нумерологом перед релизом.

## Второй визуальный референс (2026-08-03) — что взято, а что нет

Пользователь принёс второй HTML-концепт (`arcana-ui.html` + рендеры
`arcana-*.png` в корне папки) — более атмосферный стиль с фото-фонами и
живой графикой карт. Из него в `DESIGN_SYSTEM.md`/`Theme.swift` взята
**только палитра и визуальный язык** (раздел 8 DESIGN_SYSTEM.md). Осознанно
**не взято** (см. DESIGN_SYSTEM.md §8.5) — не реализовывать без явного
запроса пользователя в будущей сессии:
- Нижний таб-бар навигации (Главная/Таро/Числа/Профиль) — навигация остаётся
  через "двери" на главном экране.
- Экран «Профиль» со знаком зодиака и «Арканом рождения» — контента для
  этого нет ни в ТЗ, ни в контент-файле; астрология вообще не упоминается
  в исходниках заказчика.
- «Матрица судьбы» (квадрат Пифагора) — другая нумерологическая техника,
  не смешивать с уже реализованными числом судьбы/души/характера.
